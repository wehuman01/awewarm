日期：2026-08-25
状态：设计已完成并评审，实现尚未开始（被中断）

## 目标

Claude Code / Codex 登录账号（claude-cli / codex-cli 传输）可以像 API key 订阅一样
委托给 `awewarm serve` / `awewarm-hub serve` 保温。设计稿（已写好，含完整方案）：

    docs/superpowers/specs/2026-08-25-account-delegation-design.md

核心模型：本地读取登录凭证 → 像 API key 一样推送到服务器 RAM → 服务器以环境变量
注入跑 CLI（claude 用 `CLAUDE_CODE_OAUTH_TOKEN`，codex 用 `CODEX_HOME` 沙箱）。
本地登录永远是事实源，服务器侧刷新结果丢弃，指纹不一致时自动重推。

## 已完成的验证（spike，2026-08-25 本机实测）

- ✅ Keychain `Claude Code-credentials` 用 `security find-generic-password -w`
  可无交互读取（只验证了可读性，未记录内容）。
- ✅ codex 尊重 `CODEX_HOME`：空目录下 `codex exec` 401 无凭证报错，
  且会话状态文件写进沙箱目录（v0.149.0 实测）。
- ❓ claude `CLAUDE_CODE_OAUTH_TOKEN` **未验证完**：本机 `~/.claude/settings.json`
  配了第三方网关（ANTHROPIC_BASE_URL=api.42w.shop + kimi-k3 模型映射），
  污染了测试。重试方法：
  `echo '{}' > /tmp/s.json && CLAUDE_CODE_OAUTH_TOKEN=garbage claude -p --settings /tmp/s.json --model haiku "Reply with exactly: ok"`
  预期 401/invalid token = 环境变量被尊重；若走本地登录成功 = 需要改用
  `CLAUDE_CONFIG_DIR` 沙箱兜底方案（spec 已写明兜底路径）。
